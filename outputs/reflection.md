# 避難收容處所與空氣品質空間分析反思報告

## 1. 資料完整性 (Data Integrity)
在處理政府開放平台的原始「避難收容處所」資料時，發現顯著的品質缺失。主要問題為極端離群值與地理邊界異常：
### 1.部分點位包含 (0,0) 的無效座標
### 2.原始資料雖採用統一的 WGS84 座標系統，但存在大量點位落於台灣海峽或太平洋上，需要進行空間過濾處理。
### 3.原始資料缺乏「室內/室外」分類屬性，此為空污避難決策的關鍵變數。為解決此困境，本專案採用「語意分析與資料增強」策略。透過解析設施名稱的字串特徵，將包含「學校」、「活動中心」等高頻出現避難所推論為室內。針對無法明確歸類的名稱如「宮廟」則保留為「未知」狀態，避免強制推論造成分類失真，確保整體資料集的分析可信度。

## 2. AI 協作 (AI Collaboration)
在開發流程中，AI Agent (Windsurf Cascade) 展現出極高的實作效率。Cascade 擅長處理常規的 Python 資料處理與 GIS 套件調用，例如迅速建構 `geopandas` 的空間交集邏輯、生成 `folium` 互動式地圖，並能精準運用 `MarkerCluster` 解決大量節點渲染導致的瀏覽器卡頓問題。
然而，Cascade 在處理具備台灣在地脈絡的空間資料時，出現明顯邏輯盲點與「幻覺」。最令人惱火的是 Cascade 把 apikey 的引號刪除導致抓不到資料，挖洞給自己跳。AI 生成的邊界框 (Bounding Box) 預設邏輯過於狹隘，未能涵蓋金門、烏坵等離島，導致合法外島資料被錯誤標記為異常並剔除，也仍有在近海的點位無法被邊界框偵測。上述缺失皆需由開發者主動介入，定義精確的地理範圍與條件式邏輯方能修正。

## 3. 空間推理 (Spatial Reasoning)
採用「最近測站」的 AQI 作為避難所空氣品質的評估指標，僅能視為基礎的代理變數 (Proxy)，在嚴謹的空間推理中並不具備高度準確性。該演算法僅計算二維空間的最短歐式距離，其底層假設為「空氣品質以測站為中心呈均勻輻射變化」，此假設嚴重偏離真實的大氣物理現象。
身為主導開發者，要建立高擬真度的情境模擬，必須納入更多環境與工程變數。首先是氣象條件，「風向」與「風速」決定了污染物的傳輸路徑，位於測站下風處的避難所，其污染風險可能遠高於距離更近但位於上風處的節點。其次是物理環境限制，「地形地貌」與「都市峽谷效應」會阻斷或聚集空氣污染。再者，針對各避難所仍須考量其他資料考量交通易達性，分析計算其旅行時間。最後，針對室內避難所，戶外 AQI 不能直接等同於室內暴露風險，應評估該收容處所的建築通風率及是否配備中央空調系統 (HVAC) 與過濾設備，綜合上述變數疊加計算，方能產出具備實用價值的災防調度決策模型。
